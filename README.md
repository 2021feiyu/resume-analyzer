# resume-analyzer

**批量简历评估 + 合同条款审核：两个共用一套文档转换器的 LLM 工具。**

HR 的重复劳动有两类：看简历、看合同。两者的共同点是——**输入是文件，输出是结构化判断**。这个仓库把这两件事都做成"文件进、表格出"的批处理。

---

## 一、简历评估

```
待评估简历/ (PDF / DOCX)
      ↓ 转换器：文档 → 页面图片
      ↓ 多模态模型：提取字段 + 分类 + 五维打分
      ↓ SQLite 状态表（断点续传）
简历评估结果.xlsx
```

### 评估的不是"匹配度"，是"简历本身的质量"

提示词模板（`评估提示词模板.txt`）把评估拆成三件事：

1. **基础信息提取**：姓名、学历、院校、专业、工作年限、当前公司/岗位、期望城市……未提供的字段填「未知」，**禁止推测**。
2. **候选人分类**：按职能方向（33 个细分方向）、职级层次、行业背景归类。
3. **五维质量打分**：完整性 / 职业轨迹 / 成果呈现 / 能力深度 / 表达结构。

这样做的原因：JD 千差万别，按 JD 打分只能用于一个岗位；按简历本身打分，才能进人才库复用。要评匹配度，把 JD 塞进提示词再做第二轮即可。

### 工程细节

- **异步并发**：按模型限流配置并发数（默认按 qwen 的 RPM/TPM 设定）
- **断点续传**：`状态.db` 记录每份简历的处理状态，中断后跳过已完成
- **Word 支持**：DOCX 先转图片再送模型，避免解析器把复杂排版读成乱码
- **结果备份**：每轮输出落到 `结果备份/`，出问题可回滚

## 二、合同审核

```
待审核合同/ (PDF)
      ↓ 转换器
      ↓ 模型：条款抽取 + 风险识别
      ↓ SQLite（按文件 hash 去重，可续跑）
审核结果汇总
```

输出是**风险条款清单**：哪一条、什么风险、建议怎么改。适合把"几十份模板合同先过一遍"这种前置筛选。

## 快速开始

```bash
pip install pandas openpyxl requests Pillow PyMuPDF python-docx

cp .env.example .env          # 填入 DASHSCOPE_API_KEY

python 简历评估.py             # 简历批处理
python 合同审核.py             # 合同批处理
```

### 目录约定

| 路径 | 说明 |
|---|---|
| `待评估简历/` | 放 PDF / DOCX，可递归子目录 |
| `待审核合同/` | 放 PDF |
| `简历评估结果.xlsx` | 输出：字段 + 分类 + 五维分数 |
| `状态.db` | 断点续传状态（删掉即从头跑） |

路径都可用环境变量覆盖：`RESUME_FOLDER`、`PROMPT_FILE`、`OUTPUT_EXCEL`、`STATE_DB`、`CONTRACT_FOLDER`。

### 环境变量

| 变量 | 说明 |
|---|---|
| `DASHSCOPE_API_KEY` | 阿里云 DashScope（千问）API Key，必填 |

模型与端点在 `config.py` / `合同审核_config.py`：`MODEL`、`DASHSCOPE_BASE_URL`。换模型改这两处。

## 文件说明

| 文件 | 作用 |
|---|---|
| `config.py` | 简历分析配置（API、路径、并发） |
| `简历评估.py` | 简历评估主编排器（异步并发 + 断点续传） |
| `转换器.py` | 文档格式转换（PDF / Word → 图片） |
| `评估提示词模板.txt` | 评估规则：字段提取 + 分类 + 五维打分 |
| `合同审核_config.py` | 合同审核配置 |
| `合同审核.py` | 合同审核主编排器（SQLite 状态 + 去重） |
| `合同审核_转换器.py` | 合同文档转换器 |
| `合同审核提示词模板.txt` | 合同风险识别规则 |

---

## 注意

- **简历与合同都是敏感数据**：内容会发送到模型服务商。生产环境请脱敏，或改用私有化部署的模型端点（改 `DASHSCOPE_BASE_URL` 即可指向自建 OpenAI 兼容服务）。
- 评估结果是**初筛参考**，不构成录用或法律意见。
- 提示词模板是按技术类岗位写的，换行业需要重写分类表与维度权重。
